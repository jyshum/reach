# LLM Enrichment Pipeline — Design Spec

*Date: 2026-05-20*

---

## Overview

A one-time offline batch process that enriches 1519 raw YC company records with structured fields generated by a local LLM (Qwen3 4B via Ollama on M2 Mac). The enriched data powers the brief page, skill matching, and company filtering in REACH.

## Pipeline Position

```
scrape_yc → ml_predict → enrich (this) → normalize_tags → supabase_write
```

## Output Schema

Each company gets 7 enriched fields:

| Field | Type | Constraints | Description |
|---|---|---|---|
| `summary` | string | 2 sentences, 20-100 words | Plain-English explanation of what they build and why it matters |
| `one_liner` | string | ≤15 words | "They do X for Y" format |
| `need_tags` | string[] | 3-5 items, each ≤5 words | Specific skills a student could help with, unconstrained during generation |
| `industry` | string | From fixed list (see below) | Normalized industry category |
| `technical_level` | enum | `technical`, `mixed`, `non-technical` | How technical the product is |
| `stage_detail` | enum | `building-mvp`, `launched`, `growing`, `scaling` | What phase the company is in |
| `specific_projects` | string[] | Exactly 2 items, 5-30 words each | Concrete tasks a student could offer to do |

### Fixed Industry List

`fintech`, `healthcare`, `biotech`, `developer-tools`, `ai-ml`, `education`, `e-commerce`, `logistics`, `real-estate`, `legal`, `security`, `enterprise-saas`, `consumer`, `media`, `hardware`, `climate`, `other`

## Model & Runtime

| Parameter | Value |
|---|---|
| Model | Qwen3 4B (Q4_K_M quantization) |
| Runner | Ollama on M2 Mac (8GB) |
| RAM usage | ~3.5GB |
| Speed | ~3-4 sec/company |
| Total runtime | ~90 minutes |
| Fallback model | Phi-3 Mini 3.8B |

### Ollama API Parameters

| Parameter | Value | Reason |
|---|---|---|
| `temperature` | 0.3 | Low creativity, high consistency |
| `num_predict` | 512 | Cap output length |
| `format` | `json` | Ollama native JSON mode — forces valid JSON tokens |

## Prompt Design

### System Prompt (constant)

```
You are a startup analyst. Given a YC startup's data, extract structured information.
You MUST respond with valid JSON only. No commentary, no markdown, no explanation.
```

### User Prompt (templated per company)

```
Company: {name}
Batch: {batch}
Short description: {description}
Full description: {long_description}
Tags: {tags}
Industries: {industries}
Team size: {team_size}
Stage: {stage}

Return this exact JSON structure:
{
  "summary": "2 sentences. What they build and why it matters. Plain English, no jargon.",
  "one_liner": "10 words max. Format: '[thing] for [audience]'",
  "need_tags": ["3-5 specific skills a student intern could help with. Be specific — not 'coding' but 'Python scripting' or 'React frontend'. Base this ONLY on what the descriptions tell you about the product."],
  "industry": "one category: fintech, healthcare, biotech, developer-tools, ai-ml, education, e-commerce, logistics, real-estate, legal, security, enterprise-saas, consumer, media, hardware, climate, other",
  "technical_level": "technical | mixed | non-technical",
  "stage_detail": "building-mvp | launched | growing | scaling",
  "specific_projects": ["exactly 2 concrete tasks a student could offer to do for this company. Be specific to what this company builds — not generic. Each should be one sentence."]
}
```

### Few-Shot Examples

2-3 hand-written examples included in every prompt, showing real companies from the dataset mapped to ideal output. These anchor the model's understanding of tone, specificity, and format.

## Validation Layer

### Checks (applied to every response)

| Check | Rule | On Failure |
|---|---|---|
| Valid JSON | Response parses as JSON | Retry |
| All fields present | All 7 keys exist | Retry |
| `summary` | 1-3 sentences, 20-100 words | Retry |
| `one_liner` | ≤15 words | Retry |
| `need_tags` | List of 2-5 strings, each ≤5 words | Retry |
| `industry` | In the fixed industry list | Auto-fix to closest match, or "other" |
| `technical_level` | One of 3 valid values | Auto-fix if close, else retry |
| `stage_detail` | One of 4 valid values | Auto-fix if close, else retry |
| `specific_projects` | List of exactly 2 strings, 5-30 words each | Retry |

### Retry Logic

- Max 2 retries per company
- After 2 failures, log to `data/enrichment_failures.json` and move on
- Auto-fix over retry when possible (e.g., `"health"` → `"healthcare"`)

## Resumability

- Progress saved to `data/enriched_companies.json` every 50 companies
- On restart, skip companies already present in the output file
- Crash loses at most ~3 minutes of work

## Tag Normalization (Post-Processing)

Runs after all 1519 companies are enriched.

### Process

1. Collect all `need_tags` across all companies (~5000-7000 raw tags)
2. Programmatic first pass: fuzzy string matching to cluster near-duplicates
3. LLM pass: one call to organize clusters into a canonical vocabulary with categories
4. Output: `data/skill_vocabulary.json` — canonical skill list organized by category (estimated 100-200 unique skills)
5. Remap each company's `need_tags` to canonical terms
6. Write updated `data/enriched_companies.json`

### Purpose

The canonical skill vocabulary serves both sides of matching:
- **Company side:** Each company's `need_tags` draw from the vocabulary
- **Student side:** Onboarding UI lets students browse categories → subcategories, or type/search freely with autocomplete against the same vocabulary

## File Structure

```
backend/pipeline/
├── scrape_yc.py          # existing
├── enrich.py             # main enrichment loop
├── enrich_config.py      # prompt templates, model config, industry list
├── normalize_tags.py     # post-processing: build skill vocabulary, remap tags
```

## Output Files

| File | Contents |
|---|---|
| `data/enriched_companies.json` | All 1519 companies with original + enriched fields merged |
| `data/skill_vocabulary.json` | Canonical skill list organized by category |
| `data/enrichment_failures.json` | Companies that failed validation after retries |
